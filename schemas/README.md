# ISO 20022 schemas

The XML that Nostro writes is validated against the ISO 20022 XSD schemas. The schemas themselves are **not** stored in this repo.

## Why they are not here

Copies of these files carry SWIFT copyright notices, and some state that redistribution needs SWIFT's agreement. So this repo keeps a hash of each file, and `fetch.mjs` downloads a copy to `schemas/cache/`, which git ignores.

## Getting them

```sh
node schemas/fetch.mjs
```

The script accepts a file only if its SHA-256 matches the value pinned in `fetch.mjs`. If a schema can't be obtained, the tests that need it report SKIP rather than passing.

## Where they come from

iso20022.org is the official source, but it answers automated requests with a bot-check page, so a script can't use it. `fetch.mjs` tries these instead:

1. npm dev dependencies that ship the same file
2. The mirror at https://github.com/qianbaidu1266/ISO20022-Messages

The pinned hash is what makes this safe, not the host.

## How the hashes were chosen

| Schema | Agreement found on 7 Nov 2026 |
| --- | --- |
| `pain.001.001.03` | Mirror, `sepa-xml-ts` and `pain-001-001-03` npm packages all identical |
| `pain.001.001.09` | Mirror and `sepa-xml-ts` identical |
| `camt.053.001.08` | Mirror and `camt-parser` identical |
| `pain.002.001.10` | **One source only**, the mirror. No second copy was found to compare |

"Identical" means equal after removing any BOM and normalizing line endings and trailing whitespace. Each file's own header identifies it as generated by the ISO 20022 Standards Editor.

None of these was compared with iso20022.org directly, because of the bot check.
